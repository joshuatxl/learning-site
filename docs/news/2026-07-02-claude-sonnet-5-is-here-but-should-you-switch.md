# Claude Sonnet 5 Is Here, But Should You Switch?

<p>You can read Anthropic’s <strong><a href="https://www.anthropic.com/news/claude-sonnet-5">announcement</a></strong> and the full <strong><a href="https://www-cdn.anthropic.com/9e6a1044980d8c4ed85669faf9c2a8342e2e9f1e/Claude%20Sonnet%205%20System%20Card.pdf">system card</a></strong> if you want the official technical breakdown. What I want to focus on here is the part that matters more in daily use: what changed, why the model feels different, and why the reaction has been more mixed than Anthropic probably expected.</p><p>At a high level, Sonnet 5 is not just a faster or cleaner Sonnet 4.6.</p><p>It is a more agentic model.</p><p>That means it is built to plan more, use tools more, check its own work more, and stay inside longer coding or workflow loops. It also comes with changes to how thinking works, how effort is controlled, how much context it can use, and how safety refusals are handled.</p><p>More on those technical changes later.</p><p>The important thing to understand first is that Sonnet 5 behaves differently. It can feel more careful, more persistent, and more willing to keep working until it thinks the result is correct.</p><p>That is useful when you are building features, debugging a real codebase, or asking Claude to handle work across multiple files.</p><p>But it can also be frustrating.</p><p>For small tasks, Sonnet 5 may feel slower than Sonnet 4.6. It may think longer than needed, spend more tokens, or turn a simple request into something heavier. Some users also say it second-guesses itself more than they expected.</p><p>That is where most of the backlash seems to be coming from.</p><h2><strong>Why Many Aren’t Happy With Sonnet 5</strong></h2><p>A lot of it comes from a mismatch between what Anthropic appears to have optimized for and what many users wanted.</p><p>On Hacker News, one commenter <strong><a href="https://news.ycombinator.com/item?id=48736605">couldn’t see the point of Sonnet 5</a></strong> when dropping Opus to a lower effort setting gets similar results for less money past medium effort.</p><p>Well… that is a fair question.</p><p>On Reddit, another user said the model <strong><a href="https://www.reddit.com/r/claude/comments/1uke9te/you_thought_sonnet_46_was_bad_sonnet_5_is_worse/">felt worse than 4.6</a></strong>, mainly because of that second guessing.</p><p>For long coding jobs, it can help. A model that catches its own mistakes, updates its plan, and runs extra checks is usually better than one that rushes to a confident answer.</p><p>But for small edits or simple writing tasks, that same behavior can feel like overthinking.</p><h2><strong>5 Technical and Behavioral Changes to Sonnet 5</strong></h2><p>Here are the most interesting changes that Anthropic introduced in the new model:</p><h3><strong>1. Locked Sampling Parameters</strong></h3><p><strong>Before Sonnet 5</strong>, developers had to micromanage the model’s reasoning manually.</p><p>If you wanted Claude to “think” before answering, you used type: “enabled” and had to set a hard budget_tokens limit (e.g., 32,000 tokens). This meant you were forcing a binary choice on the model: you explicitly told it to think, and you guessed how many tokens it would need to figure out the problem.</p><p>If you set the budget too low, the model’s thought process would get cut off, breaking the response. If you set it too high, you risk overpaying for simple queries.</p><p><strong>In Sonnet 5</strong>, thinking is adaptive and on by default<strong>.</strong> You no longer specify a token budget. Instead, you use type: “adaptive”.</p><p>Anthropic made this change for two main reasons:</p><ol><p><strong>Context-Aware Scaling:</strong> The model now decides for itself when deeper reasoning is needed. If you ask it to fix a typo, it skips the thinking phase entirely, saving you latency and token costs.</p><p><strong>The “Effort” Parameter Replaces Budgets:</strong> Instead of making developers guess raw token limits, Anthropic introduced a new effort parameter (with options like low, medium, high, and max).</p></ol><p>Anthropic realized that forcing developers to guess a specific token budget was brittle and inefficient. Moving to adaptive thinking abstracts away the token math and lets the model scale its reasoning to the exact difficulty of the prompt.</p><p>So, in summary, every developer should be aware of the new thinking parameters for Sonnet 5:</p><pre># Not supported on Claude Sonnet 5 (returns 400)
thinking = {&quot;type&quot;: &quot;enabled&quot;, &quot;budget_tokens&quot;: 32000}

# Use this instead
thinking = {&quot;type&quot;: &quot;adaptive&quot;}</pre><p>You can still turn thinking off for lightweight tasks, but manual thinking budgets are gone.</p><h3><strong>2. 1M Context Window by Default, No Smaller Variant</strong></h3><p>Sonnet 5 ships with a default 1 million token context window. There is no smaller context variant. Like Opus 4.8, Sonnet 5 supports up to 128k output tokens.</p><p>Those tokens do not go as far as they used to. It uses an updated tokenizer that produces approximately 30% more tokens for the exact same text compared to Sonnet 4.6. This means the actual text capacity of the context window is noticeably smaller than in previous generations.</p><h3><strong>3. Polite Cybersecurity Refusals</strong></h3><p>Sonnet 5 is the first Sonnet tier model with live cybersecurity safeguards baked in. If it catches a prohibited or high-risk cybersecurity prompt, it does not throw an API error. Instead, it returns a successful HTTP 200 response with a stop reason of refusal.</p><h3><strong>4. Sonnet 5 is Built for Agentic Loops</strong></h3><p>The final release leans heavily toward agentic reliability, especially coding, tool use, and long-running workflow tasks. It scored 63.2 percent on SWE Bench Pro because it is optimized to navigate codebases, execute terminal commands, and correct itself when a tool call fails.</p><p>This makes it the default engine for autonomous tools like Claude Code.</p><h3><strong>5. Sonnet 5 is Slower than Sonnet 4.6 on Simple Tasks</strong></h3><p>Because Sonnet 5 defaults to adaptive thinking, developers have found that it is noticeably slower than Sonnet 4.6 on simple tasks.</p><p>According to CodeRabbit’s review of Sonnet 5, it spends time doing tests even for small changes, second-guesses its own plan, and rewrites it mid-task more often than developers would like.</p><p>We found Sonnet 5 to be slower than Sonnet 4.6, which is likely due to the extra thinking Sonnet 5 performs… It does sting when you’re waiting on a small change. Where 4.6 hands back a quick answer, 5 keeps working for a better one, and you feel that most on the little stuff.</p><p>Essentially, Sonnet 5 is built for long, open-ended autonomous work where you can walk away and let it run. I bet this would be a great model for Loop Engineering.</p><h3><strong>Is Claude 5 More Expensive than Opus 4.8?</strong></h3><p>Before you get too excited and deploy Sonnet 5 into long-horizon tasks, you must know that the model consumes more tokens than Opus 4.8. This is based on Artificial Analysis’ Cost per <strong><a href="https://artificialanalysis.ai/#price-and-cost">Intelligence Index Task</a></strong> benchmarks.</p><p>People on Reddit are <strong><a href="https://www.reddit.com/r/singularity/comments/1uk22hk/claude_sonnet_5_is_both_more_expensive_and_less/">complaining about this too</a></strong>.</p><p>Here is why the data shows Sonnet 5 costing more on that specific benchmark, and how its intelligence actually compares to Opus 4.8.</p><p><strong>Price Per Token vs. Cost Per Task</strong></p><p>If you look at the raw API costs, Sonnet 5 is the cheaper model:</p><ul><p><strong>Claude Sonnet 5:</strong> $3 per 1M input tokens / $15 per 1M output tokens. <em>(Note: It has a promotional $2/$10 pricing until Sept 1, 2026, but benchmarks use standard pricing)</em></p><p><strong>Claude Opus 4.8:</strong> $5 per 1M input tokens / $25 per 1M output tokens.</p></ul><p>You can learn more about the per-token price for each model on this <strong><a href="https://platform.claude.com/docs/en/about-claude/pricing">Model pricing page</a></strong>.</p><p>The reason Sonnet 5 appears more expensive on the leaderboard is due to <strong>token volume at maximum effort</strong>.</p><p>When running the “Artificial Analysis Intelligence Index,” the testers set Sonnet 5 to its “max effort” setting. At this tier, Sonnet 5 behaves highly autonomously: it runs through complex loops, uses tools, checks its own work, and generates massive amounts of text.</p><p>You can see this Max option in Claude’s model selector menu.</p><p>You can also see this when you bring up the /effort menu in Claude Code and set it to Max. There is a warning message below the terminal UI.</p><p>“May use excessive tokens resulting in long response times or overthinking.”</p><p>During the evaluation, Sonnet 5 generated roughly 300 million output tokens (compared to an average of ~87 million for other models), taking roughly 3x more agentic turns than previous models.</p><p>Because the benchmark calculates cost by multiplying the token price by the total tokens used, Sonnet 5’s sheer verbosity drove its final price to ~$2.29 per task, about 15% higher than Opus 4.8, which requires far fewer tokens and steps to arrive at its answers.</p><h3><strong>Should You Switch to Sonnet 5?</strong></h3><p>I would, but not everywhere.</p><p>Sonnet 5 looks like the better choice for serious coding work. It is better at handling larger tasks, following through on multi-step changes, and checking its own work before handing it back. If you use Claude for building features, refactoring, debugging, or agent-style workflows, the upgrade makes sense.</p><p>But I would not blindly make it the default for everything.</p><p>The model can be heavier than you expect. It tends to think longer, produce more, and spend more tokens than a simple task needs. For quick edits, small fixes, or routine code review, that extra effort can turn into slower runs and higher cost without much upside.</p><p>Here’s my simple take: Use Sonnet 5 for the work where quality matters more than speed. Keep your current setup for small, repetitive tasks until the pricing and latency feel easier to justify.</p><h3><strong>References:</strong></h3><ul><p>Sonnet 5 official blog post: <strong><a href="https://www.anthropic.com/news/claude-sonnet-5">https://www.anthropic.com/news/claude-sonnet-5</a></strong></p><p>Claude Sonnet 5: <strong><a href="https://www-cdn.anthropic.com/9e6a1044980d8c4ed85669faf9c2a8342e2e9f1e/Claude%20Sonnet%205%20System%20Card.pdf">https://www-cdn.anthropic.com/9e6a1044980d8c4ed85669faf9c2a8342e2e9f1e/Claude%20Sonnet%205%20System%20Card.pdf</a></strong></p></ul><p>Follow <strong><a href="https://x.com/@AlphaSignalAI">@AlphaSignalAI</a></strong> for more content like this.</p>
