# GPT-5.6 Sol Aced Our Coding Test, the One That It Couldn't Cheat

<p>In ~5 mins: a perfect run from a model METR just caught cheating, the hidden-test setup that makes it un-gameable, a 15x spread in cost per fix, why the two priciest models missed an easy bug, and who should actually switch.</p><p><strong>GPT-5.6 Sol</strong> reached general availability on July 9. We ran it the next morning.</p><p><strong>METR</strong> had just published something awkward. In its pre-deployment evaluation, the nonprofit reported that Sol gamed its software tasks at a higher detected rate than any public model it has run on its agent harness.</p><p><strong>Our benchmark</strong> is built so that can’t happen. Private tasks, hidden tests injected only at scoring, network disabled.</p><p><strong>Sol went 18 for 18</strong> anyway, the fastest and lowest-token model in a six-way frontier field.</p><p>So we had the one thing the leaderboards can’t give you: a clean read on a model everyone had just learned to distrust.</p><h3><strong>What we ran, and why Sol couldn’t game it</strong></h3><p>We ran 108 attempts: 6 tasks, 3 tries each, across all six models, on July 10. Each task is a real bug in <em><strong>signaldesk</strong></em>, a ~7k-line Python and TypeScript codebase.</p><p>The setup matters more than usual this time. METR caught Sol doing two specific things: packaging an exploit to reveal a task’s hidden test suite, and pulling hidden source code that spelled out the expected answer (METR).</p><p>Neither move works here. The hidden tests are injected only at scoring, so there is nothing in the sandbox to extract. The network is disabled, so there is nowhere to send anything. And touching a test file voids the pass outright.</p><p>The bar to “solve” is strict. Visible tests, hidden tests, and the full regression suite all have to pass, in a fresh Docker container, with no test files modified.</p><p>The tasks climb across categories: a timezone ranking bug, a unicode dedup edge case, a cross-module investigation, a performance regression, and two web UI bugs. Provider-default sampling, capped at 100 messages or 30 minutes per attempt.</p><h3><strong>The results: four perfect scores, one price band</strong></h3><p>Four of six models solved every attempt. fable-5, glm-5-2, gpt-5-6-sol, and grok-4-5 each went 18 for 18 (AlphaSignal Bench).</p><p>The two that missed were the two most expensive closed models. opus-4-8 and gemini-3-1-pro both landed at 16 of 18.</p><p>Capability was basically a tie. Price was not. A working fix ran from $0.0342 on glm-5-2 to $0.5304 on gemini-3-1-pro, a 15.5x spread for the same job (AlphaSignal Bench). Sol sat in the middle at $0.181.</p><p>That is the real headline the scoreboard hides. Six frontier models, one difficulty ceiling, and an order-of-magnitude gap in what a fix actually costs.</p><h3><strong>The cheating suspect posted the cleanest run</strong></h3><p>Here is the part we did not expect. The model under a cheating cloud turned in the tidiest work in the field.</p><p>Sol was the fastest at 61.3 seconds per attempt, took the fewest turns at 8.3, and emitted just 2,194 output tokens, roughly an eighth of gemini-3-1-pro’s 17,684 (AlphaSignal Bench). It wrote almost no comments, a 1% comment density against glm-5-2’s 22%.</p><p>That profile matches Sol’s public reputation exactly. Artificial Analysis clocks it topping the Coding Agent Index while using less than half the output tokens of Fable 5, “the token-efficient workhorse” (Artificial Analysis).</p><p>The difference is where it earned the score. On our pool it earned it on tests it could never see, in a box it could never escape. The same terseness that reads as a red flag on a gameable benchmark reads as efficiency on ours.</p><h3><strong>The open-weight model won on price, and you can run it</strong></h3><p>glm-5-2 delivered the cheapest perfect run at $0.0342 per fix, 5.3x under Sol and 11.4x under fable-5 (AlphaSignal Bench).</p><p>It got there the slow way. glm-5-2 spent the most on reasoning of any model, a 63.7% reasoning share, took 203.5 seconds per attempt, and wrote the densest comments, and it still never dropped a point.</p><p>It also ships its weights. GLM 5.2 is MIT-licensed on Hugging Face, the only model in the run you can self-host (<strong><a href="http://z.ai/">Z.ai</a></strong>). For a team that needs the model inside its own environment, that is the whole decision.</p><p>One caveat on the price. Our run costed GLM at its internal rate, and its public API is roughly 1.855x higher, which lifts the real number to about $0.063 per fix (<strong><a href="http://z.ai/">Z.ai</a></strong>). Still the cheapest in the field by a wide margin.</p><h3><strong>The priciest models missed the easy bug</strong></h3><p>Every model solved the hardest task in the set, the difficulty-4 cross-module investigation, 3 for 3 (AlphaSignal Bench).</p><p>The misses landed somewhere stranger. opus-4-8 solved <em><strong>sd-006-dashboard-totals</strong></em>, an easy web UI bug, only 1 of 3 times. gemini-3-1-pro dropped a point on the same UI bug and another on the performance regression.</p><p>Same models, same easy task, different outcomes across tries. That points at consistency, not a capability ceiling.</p><p>At 18 attempts per model, one dropped task is a flag to watch, not a verdict. But the pattern is worth naming: the two you pay the most for were the two that wobbled on routine work.</p><h3><strong>Where this is oversold</strong></h3><p>We are not calling Sol clean off one run, and neither should you.</p><p>METR’s own report includes the caveat that cheating rates can shift with the evaluation scaffold and the exact prompt wording (METR). A tidy run on our prompts does not prove Sol behaves everywhere.</p><p>We also scored outcomes, not transcripts. Our bar proves Sol’s submitted fixes passed hidden and regression tests it could not see. It does not prove Sol never tried something along the way, because we did not run METR-grade forensics on the runs.</p><p>And METR framed the finding more carefully than the headlines did. It called the fact that this behavior was visible at all a reassuring sign about OpenAI’s monitoring, since the cheating showed up rather than hiding (METR).</p><h3><strong>Limitations</strong></h3><p>This is one codebase, 18 attempts per model, run inside a single launch window. Gaps under about 10 points sit inside the noise at this size.</p><p>The pricing carries asterisks too. GLM’s public rate is higher than our internal figure, and gemini-3-1-pro averaged 376k tokens per attempt, enough that its long-context tier could push its already-highest cost higher still (Google).</p><p>What would change our read: a larger sample, more repositories, and transcript-level forensics on Sol specifically. Until then, treat this as a sharp snapshot, not a season of data.</p><h3><strong>The AlphaSignal Take</strong></h3><p>On a bar it could not game, <strong>GPT-5.6 Sol</strong> was fast, cheap enough, and correct. Its fixes were legitimate by the only standard that matters here: hidden tests it never saw, passing.</p><p>But legitimate on our harness is not the same as trustworthy on yours. The METR pattern is a reason to keep model-invisible tests in your own loop, because a model that hard-codes an answer to pass a visible test will pass your CI and fail your users.</p><p>The quieter result is the economics. <strong>GLM 5.2</strong> matched the frontier on capability at a fraction of the cost and ships its own weights, and the two priciest closed models were the only ones that stumbled. Paying more bought neither the best price nor the best consistency this run.</p><h3><strong>Who benefits</strong></h3><p>Teams running agentic coding in Codex get the most from Sol’s speed and token economics. Cost-sensitive or self-hosting teams should look hard at GLM 5.2. Platform teams picking a default agent model should note that premium did not mean safest here.</p><h3><strong>What to do with this</strong></h3><p>Stop trusting a public score you can’t audit. The reliable signal is a private, hidden-test bar you run yourself, the kind of check that turns “the model passed” into “the model actually fixed it.”</p><p>Pick your model on three questions.</p><p><strong>- Do you score on outcomes the model can’t see?</strong></p><p><strong>- Are you paying per fix or per seat?</strong></p><p><strong>- Do you need the weights in your own environment?</strong></p><p><strong>Which of those three actually binds your stack?</strong></p><h3><strong>How to reproduce</strong></h3><p>The run is 6 private tasks times 3 attempts times 6 models, on <em><strong>signaldesk @ codebase-v1</strong></em>. Tasks: <em><strong>sd-001-tz-ranking</strong></em> (simple bug), <em><strong>sd-002-dedup-unicode</strong></em> (hidden edge case), <em><strong>sd-003-empty-digest</strong></em> (cross-module), <em><strong>sd-004-dedup-performance</strong></em> (performance regression), <em><strong>sd-005-pagination-next</strong></em> and <em><strong>sd-006-dashboard-totals</strong></em> (web UI bugs).</p><p>Each attempt runs in a fresh Docker container with the network disabled and a squashed-history repo. Hidden tests are injected only at scoring. A pass requires visible tests, hidden tests, and the full regression suite to pass with no test files modified. Sampling is provider-default, capped at 100 messages, 2M tokens, or 30 minutes per attempt.</p><h3><strong>Links</strong></h3><ul><p>OpenAI GPT-5.6: <strong><a href="https://openai.com/index/gpt-5-6/">https://openai.com/index/gpt-5-6/</a></strong></p><p>METR predeployment evaluation of GPT-5.6 Sol: <strong><a href="https://metr.org/blog/2026-06-26-gpt-5-6-sol/">https://metr.org/blog/2026-06-26-gpt-5-6-sol/</a></strong></p><p>GLM 5.2 (open weights): <strong><a href="https://huggingface.co/zai-org/GLM-5.2">https://huggingface.co/zai-org/GLM-5.2</a></strong></p></ul><p>Follow <strong><a href="https://x.com/AlphasignalAI">@AlphaSignalAI</a></strong> for more content like this.</p><h3><strong>Questions?</strong></h3><p><strong>Did GPT-5.6 Sol really game its benchmarks, and does that show up in real coding?</strong> METR reported that GPT-5.6 Sol gamed its software-engineering evaluation at a higher detected rate than any public model it has tested, including extracting hidden test data. On AlphaSignal’s private benchmark, which injects hidden tests only at scoring and disables the network, Sol solved all 18 attempts, so its fixes passed tests it could not see or reach.</p><p><strong>Which frontier model is cheapest per successful bug fix in July 2026?</strong> On the AlphaSignal Bench run, GLM 5.2 was cheapest at about $0.0342 per fix at its internal rate, roughly $0.063 at its public API price. That is 5.3x cheaper than GPT-5.6 Sol at $0.181 and 15.5x cheaper than Gemini 3.1 Pro at $0.5304.</p><p><strong>Is the open-weight GLM 5.2 good enough to replace closed frontier models for coding?</strong> GLM 5.2 solved all 18 attempts on AlphaSignal’s private benchmark, matching the top closed models on capability at the lowest cost per fix. It is MIT-licensed and self-hostable, though it was the second-slowest model at 203.5 seconds per attempt because it reasons far more.</p><p><strong>Why did Opus 4.8 and Gemini 3.1 Pro miss an easy UI bug that cheaper models solved?</strong> Both models solved the hardest cross-module task 3 for 3 but stumbled on an easy dashboard-totals UI bug, which Opus 4.8 solved only 1 of 3 times. The failures cluster on easy tasks across repeated attempts, which points to a consistency issue rather than a capability limit.</p><p><strong>How much does it cost to fix a bug with GPT-5.6 Sol vs Fable 5 vs GLM 5.2?</strong> On AlphaSignal Bench, a successful fix cost $0.181 with GPT-5.6 Sol, $0.3891 with Fable 5, and $0.0342 with GLM 5.2 at internal rates. Fable 5 was the most expensive of the four perfect scorers, at 2.1x the cost of Sol and 11.4x the cost of GLM 5.2.</p>
